## 1. 背景

开发板是圆形 1.75 寸 AMOLED、铝合金挂绳外壳、电池与充电、BLE / Wi-Fi、双麦喇叭、六轴 IMU。仓库已有厂商样例和 `app/` 固件骨架，但还没有产品定义。

要做成**可佩戴的电子徽章**，不是缩小版手机、手表或导航仪。

## 2. 目标与非目标

### 目标

- 胸前一眼能看清身份（名字、头像或短标题）。
- 手机或电脑通过 BLE 改内容，掉电后仍在。
- 可查看电量、充电状态；PWR 能开关机或亮屏。
- 可选一屏显示 **Codex / 用量额度**（由手机推送数字，设备不登录 OpenAI）。

### 非目标（v1 不做）

- 离线地图、城市瓦片包
- GNSS 导航（本板无 GPS）
- 完整语音助手 / 大模型端侧推理
- Brookesia 式多应用桌面
- 健康手环（仅有 IMU，无心率等）
- 设备直连 ChatGPT / Codex 账号

## 3. 用户与场景

| 用户 | 场景 |
| --- | --- |
| 展会参会者 | 挂胸前当电子工牌，别人扫一眼名字和公司 |
| 开发者 | 工位或包上挂着，看剩余 Codex / API 额度 |
| 活动主办 | 统一改标题（如桌号、环节名） |

主场景：**展示 + 被改内容**。不是在吧唧上完成复杂操作。

## 4. 硬件约束（需求必须遵守）

| 约束 | 对产品的含义 |
| --- | --- |
| 无 TF / microSD | 内容只放 Flash / NVS，禁止地图包、歌库 |
| Flash 32 MB（程序约 8 MB，资源最多再约十几 MB） | 头像一张小图；额度只存几个数字 |
| PSRAM 8 MB（堆，非常驻资源盘） | 解码、LVGL 缓冲，不当存储 |
| 无独立 RTC、无 GPS | 时间靠开机后对时或手机写入；无定位 |
| 466×466 圆屏 | 主视觉居中、大字、少按钮 |
| 续航靠 3.7 V 电池 | 默认息屏，翻腕或点按亮屏 |

## 5. 产品形态

一块吧唧，**多张「脸」（Face）**，同一套 BLE 写入协议。

| Face | v1 | 说明 |
| --- | --- | --- |
| 身份卡 | 必须 | 标题、副标题、可选头像 |
| 额度环 | 必须（数据可空） | 显示剩余百分比 / credits，无数据时显示占位 |
| 设置 | 必须 | 亮度、电量、固件版本、BLE 名 |

左右滑动或点主页按钮切换身份卡 ↔ 额度环。设置从主页进入，不作为常亮脸。

## 6. 功能需求

### 6.1 身份卡（P0）

- 显示 `title`（必填，默认 `E-Badge`）、`subtitle`（可空）。
- 可选一张头像：JPEG/PNG，单边 ≤ 200 px，文件 ≤ 64 KB，存在 Flash。
- 无头像时用首字或纯色底。
- 文字默认支持中英文（需中文字体，至少常用 3k 字或位图方案，体积可控）。

### 6.2 内容写入与持久化（P0）

- BLE 可发现，广播名 `E-Badge`（可后续改成 title 截断）。
- GATT 可写：title、subtitle、当前 Face、额度字段。
- 写入后立刻刷新屏幕，并写入 NVS（头像写 SPIFFS）。
- 掉电重启后恢复上次内容。

### 6.3 电源与按键（P0）

- 接入 AXP2101：电量百分比、充电中。
- 设置页与身份卡角标可看电量。
- 低电（如 &lt; 15%）降低亮度并提示。
- PWR：短按亮屏/息屏，长按关机（与硬件电源键行为对齐，实现时以原理图为准）。
- BOOT：开发用，产品态不作为主交互。

### 6.4 亮屏策略（P0）

- 亮屏超时默认 10 s（设置里可改 5 / 10 / 30 s）。
- 点按屏幕或翻腕（IMU 挑手腕，P1 可降级为仅点按）重新计时。

### 6.5 Codex / 用量额度脸（P0 显示，P1 数据源）

**设备侧（P0）**

- 环形进度：`used_percent` 或 `remain_percent`（0–100）。
- 主数字：`remain_label`（如 `128 cr` 或 `72%`），由手机决定文案，设备不解释 credits 算法。
- 副文案：`quota_caption`（如 `Codex 5h` / `Weekly`），可空。
- `updated_at` 可选；超过 24 h 未更新显示「数据过期」。
- 从未写入过：环为空，文案「在手机里连接后同步」。

**手机 / 电脑侧（P1，本仓库固件不包含）**

- 在已登录环境读取用量，经 BLE 推送到设备。
- **禁止** 把 ChatGPT / Codex session、refresh token 写入徽章。
- Codex 订阅额度无稳定公开嵌入式 API；官方以 Codex Usage 面板为准。配套脚本可用用户本机登录态，不作为固件依赖。

**非目标：** 徽章上购买 credits、登录 OpenAI、精确复刻官网账单。

### 6.6 语音与 IMU（P2）

- IMU：翻腕亮屏（P1）、摇一摇切脸（P2）。
- 喇叭：写入成功短提示音（P2）。
- 麦克风：v1 不用。

## 7. 交互草案（圆屏）

**身份卡**

- 中：头像或首字
- 中下：title（大）、subtitle（小）
- 上：电量小点；充电时闪烁
- 底：小点指示当前脸（身份 / 额度）

**额度环**

- 外圈：已用或剩余比例
- 圆心：remain_label
- 圈下：quota_caption
- 过期：圈变灰 +「数据过期」

**设置**

- 亮度滑条、超时、电量、版本、复位内容

手势：单击亮屏；左右滑切脸；长按进设置。控件要大，适合拇指、避免密集列表。

## 8. 数据与 BLE（草案）

内容模型（固件 `badge` 组件）：

```text
title            string  ≤ 32
subtitle         string  ≤ 64
face             enum    identity | quota
remain_percent   uint8   0–100，255 = 未知
remain_label     string  ≤ 16
quota_caption    string  ≤ 24
quota_updated_at uint32  unix，0 = 无
```

GATT 建议：

- 广播：可连接，名称 `E-Badge`
- 服务：自定义 128-bit UUID（实现时锁定，写入本文档附录）
- 特征：身份 JSON 或定长字段（UTF-8）；额度同上；头像用单独特征或分片写（P1）
- 读：当前内容；写：更新并回读校验

不在 BLE 上传账号、Cookie、API Key。

## 9. 非功能需求

| 项 | 要求 |
| --- | --- |
| 固件 | ESP-IDF 5.5+，代码在 `app/`，不改 `examples/` 当产品 |
| 启动 | 点亮身份卡 &lt; 3 s（冷启动目标） |
| 连接 | BLE 写入到上屏 &lt; 1 s |
| 功耗 | 息屏待机为目标场景；常亮只作调试 |
| 安全 | NVS 无密钥；额度只是展示数字 |
| 版本 | 设置页显示 `x.y.z` + git hash |
| 升级 | v1 可用 USB 烧录；OTA 为 P2 |

## 10. 里程碑

| 阶段 | 范围 | 完成标准 |
| --- | --- | --- |
| M0 | 结构 | `app/` 能编过、开屏（骨架已有） |
| M1 | 身份闭环 | BLE 改 title/subtitle，重启仍在，PWR 亮灭屏 |
| M2 | 电源 | 电量、充电、低电 |
| M3 | 额度脸 | 显示推送的环和文案；无数据占位；过期态 |
| M4 | 抛光 | 中文字体、头像、翻腕、提示音 |

配套「电脑推送 Codex 数字」的脚本或小工具放仓库 `tools/`，属 M3，不阻塞 M1。

## 11. 成功标准（M3）

1. 陌生人 1 米内能读清名字。
2. 手机改名字后屏幕马上变，拔电池再插仍是新名字。
3. 手机推送 `remain_percent=35` 后，额度环约为 1/3，文案与 `remain_label` 一致。
4. 不连接 OpenAI 也能演示身份卡；额度脸无数据时不崩溃、有占位。

## 12. 开放问题

1. 头像 v1 是否必须，还是 M4 再做？
2. BLE 用 JSON 还是定长二进制？（建议 v1 JSON，字段少）
3. 额度环表示「剩余」还是「已用」？默认 **剩余**。
4. 是否需要第二额度（5 小时窗 vs 周限额）？v1 只一环，caption 区分。

# 产品需求文档：开发者桌面状态徽章

| 项目 | 内容 |
| --- | --- |
| 产品名 | 开发者桌面状态徽章 |
| 硬件 | Waveshare ESP32-S3-Touch-AMOLED-1.75C |
| 固件 | `app/`，ESP-IDF 5.5+ / LVGL 9 |
| 产品阶段 | v1.0 草案 |
| 基线 | 在现有“额度屏”固件与 BLE JSON 协议能力上演进 |

## 1. 产品定义

一个放在显示器边、桌面底座或挂绳上的圆形状态终端。它把开发者在工作时最需要“一眼看到”的少量信息，以高对比度、低打扰的方式呈现在 1.75 英寸圆形屏幕上。

首版不是第二台电脑，也不是完整智能手表。它只显示经过电脑端或局域网服务筛选后的状态；设备负责可靠展示、轻交互、离线保留最后数据和低电管理。

**一句话：** 抬眼一秒，就知道额度、构建、专注和下一件事是否需要处理。

## 2. 目标与非目标

### 2.1 目标

- 在约 1 米距离可清楚读取当前最重要的状态。
- 让电脑端工具在 1 秒内把状态推送到设备并刷新画面。
- 断电重启后仍保留各卡片最后一次有效数据。
- 默认息屏，触摸或 PWR 短按唤醒；低电时自动降亮度。
- 在没有手机 App 的前提下，先通过 BLE 完成可靠使用；Wi-Fi/MQTT 作为后续扩展。

### 2.2 非目标

- 不在设备上保存账号、浏览器登录信息、接口密钥、源码或个人日历详情。
- 不做登录、支付、消息完整收件箱、网页浏览器或复杂多任务。
- 不做独立 GPS 导航、NFC 支付、持续录音、离线语音识别。
- 不承诺作为精确时钟：板上无 RTC，时间须从推送端或 Wi-Fi 校时获得。

## 3. 用户与场景

唯一核心用户为长时间面对电脑工作的开发者。

| 场景 | 用户动作 | 徽章反馈 |
| --- | --- | --- |
| 代码工作 | 抬头一瞥 | 显示当前主卡，例如代码助手剩余额度 |
| 构建失败 | 电脑端工具推送失败状态 | 红色状态点、卡片摘要和可选短提示音 |
| 专注工作 | 开启 25/50 分钟计时 | 环形进度、剩余分钟和休息提醒 |
| 即将开会 | 日历同步工具推送 | 显示会议倒计时与简短标题 |
| 离开桌面后返回 | 点按屏幕或短按 PWR | 恢复上次卡片，不要求重新连接 |

## 4. 信息架构与交互

### 4.1 卡片

v1 采用最多四张可配置卡片；同一时刻只显示一张，避免在圆屏堆叠过多文字。

1. **代码助手额度**：剩余百分比或额度数值、额度窗口说明、更新时间。
2. **构建状态**：项目名缩写、成功/运行中/失败、分支或构建号。
3. **专注计时**：剩余时间、当前模式（专注/休息）、进度环。
4. **日程提醒**：距离下一会议的倒计时和最多一行标题。

设备应优先显示“需要行动”的卡片：失败构建 > 即将开始的会议 > 专注倒计时 > 用户固定的默认卡片。用户也能手动切到其他卡片。

### 4.2 操作

| 操作 | 行为 |
| --- | --- |
| 点按主页 | 唤醒；亮屏时切换到下一张卡片 |
| 长按主页 | 打开设置 |
| PWR 短按 | 息屏时唤醒；亮屏主页时打开设置 |
| PWR 长按 | 请求 PMU 关机 |
| 设置页 | 亮度、息屏时间、卡片顺序、提示音、清除数据、版本信息 |

不支持左右滑动分页、文字输入和复杂手势。

### 4.3 主界面

所有卡片使用统一构图：

```text
             ● 状态点 / 连通性
        ┌─────────────────┐
        │     圆形进度环   │
        │   72% / 18:24   │
        │  代码助手 5小时  │
        └─────────────────┘
        刚刚更新 · 点按切换
```

- 中央为不超过 16 个 UTF-8 字节的主数值或短文本。
- 下方为不超过 24 个 UTF-8 字节的说明文字。
- 外环表示进度、剩余量或紧迫程度；无自然进度含义时显示细环或状态色。
- 失败使用红色，警告使用琥珀色，正常使用主题色，离线/过期使用灰色。仅颜色不能作为唯一状态表达，须同时显示图标或文字。

## 5. 状态与优先级

| 状态 | 触发条件 | 展示 | 优先级 |
| --- | --- | --- | --- |
| 严重 | 持续集成失败、服务故障 | 红点、失败卡片、可选提示音 | 最高 |
| 临近 | 会议 <= 10 分钟、专注结束 <= 2 分钟 | 琥珀点、倒计时卡片 | 高 |
| 正常 | 数据新鲜且无告警 | 默认或用户选中卡片 | 普通 |
| 过期 | 单张卡片超过其 TTL 未更新 | 灰色环、`数据过期` | 低 |
| 未配置 | 没有任何有效卡片 | 占位和 `连接后同步` | 最低 |

建议有效期：代码助手额度 24 小时；构建状态 2 小时；专注计时由本机单调时钟继续计算，重启后需要推送端校正；日程提醒 15 分钟。

## 6. 数据同步与隐私

### 6.1 v1：BLE 推送

电脑端常驻小工具发现广播名 `Codex`，连接后向现有 GATT 服务写 JSON。

| 项 | 值 |
| --- | --- |
| 服务 UUID | `0xFF00` |
| 旧额度特征 UUID | `0xFF01` |
| 仪表盘特征 UUID | `0xFF02` |
| 方向 | 两个特征均可读写；写入后设备持久化并刷新 |

为兼容已有额度屏，保留 `0xFF01` 的四字段 JSON。桌面状态徽章 v1 在同一服务新增特征 **`0xFF02`**，承载完整多卡片快照；不要复用字段来传递身份或密钥。

`0xFF02` 只接受一次性替换全部卡片的快照，不支持增量合并。载荷上限为 1023 UTF-8 字节；客户端应使用带响应写入，设备会在 JSON、字段和卡片集合全部校验通过后才写入 NVS。读取 `0xFF02` 会返回当前完整快照。

| 字段 | 规则 |
| --- | --- |
| `version` | 固定为 `1` |
| `default_card` | 必须是快照中存在的 `quota` / `build` / `focus` / `schedule` 之一 |
| `cards` | 1–4 项；ID 不可重复 |
| `percent` | `0–100`，或 `255` 表示无自然进度 |
| `label` / `caption` | 分别最多 16 / 24 个 UTF-8 字节 |
| `updated_at` / `ttl_sec` | 正 Unix 秒；有效期为 1 秒至 7 天 |
| `severity` | `normal`、`near`、`critical` |
| `target_at` | 专注和日程卡必填，且必须晚于 `updated_at` |

旧客户端继续向 `0xFF01` 写额度 JSON。若仪表盘快照已经存在，旧值会同步映射并覆盖其中的 `quota` 卡；尚未收到仪表盘快照时，主页继续按旧额度屏模式显示。

建议的逻辑数据模型：

```json
{
  "version": 1,
  "default_card": "quota",
  "cards": [
    {
      "id": "quota",
      "percent": 72,
      "label": "72%",
      "caption": "代码助手 5小时",
      "updated_at": 1780000000,
      "ttl_sec": 86400,
      "severity": "normal"
    }
  ]
}
```

固件只接受校验通过的展示字段，不解析网页内容、不计算消费额度、不处理凭证。访问令牌、浏览器登录信息、接口密钥和日历原文只允许留在电脑端。

专注和日程倒计时在同一次开机期间使用 `esp_timer` 计算。板上没有 RTC，重启后这两类卡片必须显示“等待同步”，直到电脑重新推送快照；额度与构建卡会保留最后一次数据，并在当前开机周期按有效期显示过期状态。

电脑端工具位于 [`../tools/`](../tools/)，使用 Python 与 Bleak，支持扫描、读取、从文件或标准输入推送快照，以及生成四卡片示例数据。它只负责 BLE 传输，外部脚本负责取得额度、构建和日历状态。

### 6.1.1 代码助手额度浏览器连接器（实验性）

为没有公开个人额度读取接口的场景，项目提供可由用户自行加载的 Chrome/Edge 扩展和本机 BLE 转发器。用户在浏览器中自行登录 ChatGPT 后，扩展只从“设置 → 用量”页面的已渲染文本中提取一个可见百分比与时间窗口，并通过回环地址 `127.0.0.1` 发送给 Python 转发器；转发器读取已有仪表盘快照后，仅替换“代码助手额度”卡再写回 BLE。

- 扩展不申请 Cookie 权限，不读取浏览器网络请求、存储或账号资料，不向互联网发送数据。
- 默认须由用户点击“立即同步”；用户可显式开启页面变化时自动同步。
- 转发器不记录收到的用量；可选本机口令用于限制本地调用方。
- 该连接器依赖页面可见文案，ChatGPT 页面更新后可能需要同步更新解析规则；它不是 OpenAI 公共 API 的替代品。

### 6.2 后续：Wi-Fi / MQTT

v1 验收稳定后，可加入 Wi-Fi 配网和 MQTT 订阅模式，让家庭自动化服务、构建网关或桌面代理向主题推送同一套展示模型。该阶段必须提供：配网清除、断线标识、TLS/凭证安全存储策略，以及本地网络不可用时的降级展示。

## 7. 固件架构

在既有组件划分上扩展，避免把业务逻辑塞进 `app/main/`。

| 组件 | v1 责任 |
| --- | --- |
| `board` | AMOLED、AXP2101、电量、亮度、PWR、息屏唤醒 |
| `ui` | 卡片渲染、状态色、卡片切换、设置和定时刷新 |
| `badge` | 卡片数据模型、字段校验、NVS 持久化、过期判断和变更回调 |
| `ble` | 广播、GATT、JSON 分包/长度限制、写入错误映射 |
| `sensors` | 预留 IMU 的抬腕唤醒或桌面翻转检测；不阻塞 v1 |
| `audio` | 提示音开关与短音效；不采集或上传音频 |
| `tools/` | 电脑端数据连接器、统一推送命令、模拟器和日志 |

## 8. 里程碑

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| M0 | 现有额度屏稳定基线 | 开机、BLE 写入、NVS、息屏和低电正常 |
| M1 | 通用卡片模型与手动切换 | 至少“代码助手额度”与“构建状态”两卡；重启后仍显示；无花屏 |
| M2 | 桌面推送工具 | 一条命令可推送模拟数据；写入到上屏 < 1 秒 |
| M3 | 专注计时与会议提醒 | 优先级切卡、倒计时、过期状态正确 |
| M4 | 声音/IMU 可选增强 | 提示音可关闭；传感器失败不影响核心功能 |
| M5 | Wi-Fi/MQTT（可选） | 配网、重连、安全清除和离线降级通过测试 |

## 9. 验收标准

1. 冷启动在 3 秒内显示最后一张有效卡片或无数据占位。
2. BLE 写入有效数据后 1 秒内完成屏幕刷新和 NVS 持久化。
3. 1 米外可识别卡片类型、核心数字和严重状态。
4. 数据不新鲜时，不把旧数据表现为实时正常状态。
5. 构建失败、会议临近和正常额度卡片同时存在时，优先级符合第 5 节。
6. 没有电池、PMU、IMU 或音频设备的可选能力失败时，主界面和 BLE 仍可工作。
7. 固件、NVS、串口日志和 BLE 负载中不包含访问令牌、浏览器登录信息、密码、完整会议正文或源代码。
8. 息屏、亮度限制和 PWR 长按关机行为维持现有规格。

## 10. 风险与取舍

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 1.75 英寸圆屏空间有限 | 多信息会降低可读性 | 一次仅展示一张卡片；字段严格限长 |
| 无 RTC | 重启后无法可靠判断绝对过期 | 推送端带 unix 时间；同次开机使用单调计时；必要时 Wi-Fi 校时 |
| BLE 文本长度与 MTU | 大 JSON 可能失败 | v1 限制载荷和卡片数，后续再实现分片 |
| 电量计未标定 | 百分比观感不稳定 | 保留电压曲线校正，低电策略以保守阈值为准 |
| 外部服务接口变化 | 桌面连接器失效 | 在 `tools/` 隔离各数据源；固件仅认识稳定展示协议 |

## 11. v1 已拍板的决策

- 产品定位是桌面状态终端，不是通用智能手表。
- 首发同步方式是 BLE；Wi-Fi/MQTT 不是 v1 前置条件。
- 先支持代码助手额度、构建状态、专注计时和下一会议四类卡片。
- 数据源只在电脑端处理；设备端只保存必要的、长度受限的展示数据。
- 默认 10 秒息屏，低电时降亮度，设置保存在 NVS。
- 所有新功能尽量扩展实现层（`src/`）；公共接口变化遵循 [`DEVELOPMENT.md`](DEVELOPMENT.md) 的分支约定。
